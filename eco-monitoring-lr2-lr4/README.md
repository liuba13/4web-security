# ЕкоМоніторинг — єдиний навчальний застосунок (ЛР№2–ЛР№4)

Веб-система моніторингу якості повітря: станції спостереження, API екологічних
даних (PM2.5, PM10, NO₂), панель оператора. Складається з двох частин:

- `api/` — серверний застосунок на Express і MongoDB;
- `dashboard/` — панель оператора на Next.js.

> ⚠️ **Це навчальний застосунок із навмисно закладеними вразливостями. 

## Для яких лабораторних

Це один застосунок на три роботи. 
- **ЛР№2. Автентифікація та авторизація в API.** Закрити вади входу, токенів, рольового доступу, доступу на рівні об'єкта й функції, імпорту (профіль A01, A07).
- **ЛР№3. Захист від XSS, CSRF та ін'єкцій.** Закрити ін'єкції (SQL, NoSQL), міжсайтовий скриптинг, підроблений міжсайтовий запит і обробку виняткових умов (профіль A05, A10).
- **ЛР№4. Пентест, аудит за OWASP 2025 та звіт.** Провести пентест і аудит усієї системи, закрити конфігурацію й логування (профіль A02, A09), скласти звіт.

Перелік вразливостей не наводиться: їх треба знайти самостійно, спираючись на
політику доступу [`docs/ACCESS-MATRIX.md`](docs/ACCESS-MATRIX.md) і на матеріали
відповідної роботи.

## Вимоги

- Node.js **20.6 або новіший** (`node -v`); рекомендовано актуальну LTS-версію;
- npm.

Docker і окремо встановлений сервер бази даних **не потрібні**.

Пакети `better-sqlite3` і `argon2` містять нативний код. Якщо `npm ci` повідомляє
про помилку збирання (`node-gyp`), встановіть інструменти збирання: на Windows —
Python і «Visual Studio Build Tools» з компонентом «Desktop development with C++»;
на Linux — `build-essential` і `python3`.

## Швидкий старт

Команди однакові для Windows (cmd, PowerShell), Linux і macOS.

### 1. API
```bash
cd api
npm ci            # точно ті версії, що в package-lock.json
npm run dev       # http://localhost:3000
```

Перевірка: `http://localhost:3000/health` повертає `{"ok":true}`.

Під час першого запуску створюється файл `.env` (копія `.env.example`), а порожня
база автоматично наповнюється тестовими даними.

### База даних: MongoDB і SQLite

Застосунок працює з обома драйверами, код маршрутів і моделей однаковий.
Драйвер задається у `api/.env` змінною `DB_DRIVER`:

- `DB_DRIVER=mongo` (за замовчуванням) — піднімається тимчасовий MongoDB у
  пам'яті (пакет `mongodb-memory-server`). Під час першого запуску він один раз
  завантажує MongoDB з інтернету. Дані існують, поки працює сервер.
- `DB_DRIVER=sqlite` — локальний файл `api/data/ecomonitoring.db`, без сервера
  бази. Дані зберігаються між перезапусками. Цей режим потрібен, якщо MongoDB
  не завантажується (обмежена мережа), і для модуля табличної звітності.

> **Модуль звітності** (`GET /api/reports/search`) працює лише з
> `DB_DRIVER=sqlite`, оскільки використовує реляційну таблицю й текстовий SQL.
> На драйвері `mongo` цей маршрут повертає `501`.

### 2. Допоміжні сервіси (окремий термінал)

```bash
cd api
npm run mock
```

| Адреса | Призначення |
|---|---|
| `http://127.0.0.1:4100/readings.json` | зовнішнє джерело екоданих для імпорту показників |
| `http://127.0.0.1:4100/redirect?to=...` | джерело, що повертає переадресацію 302 |
| `http://127.0.0.1:4200/` | внутрішній сервіс конфігурації (має бути недосяжним через API) |

### 3. Дашборд (окремий термінал)

```bash
cd dashboard
npm ci
npm run dev       # http://localhost:3001
```

## Станції моніторингу

Станції надсилають показники на `POST /api/stations/:id/readings` із заголовком
`X-Station-Key`. Станція — недовірене джерело: усе, що вона надсилає, має
перевірятися на стороні сервера.

## Скидання навчального проєкту

```bash
cd api
npm run seed      # видаляє всі дані й наповнює базу заново
```

Для `DB_DRIVER=mongo` (база в пам'яті) достатньо перезапустити сервер.
Для `DB_DRIVER=sqlite` — `npm run seed` або видалити каталог `api/data/`.
